Scheduling contract: app open performs zero WorkManager schedule and zero cancel calls. An explicit switch change schedules or cancels when allowed. The closed build gate refuses OFF-to-ON before writing consent or scheduling; ON-to-OFF still persists OFF and cancels health work. Save schedules only when sync is ON and the interval actually changed, and never cancels. Manual and webhook-test one-time requests are explicit user actions, not consent changes. Control `setEnabled`, `save`; Activity `onCreate`; Worker `Schedule.periodic`, `Schedule.pauseHealth`, `Schedule.manual`.

## Flow

| From | Action | Result and implementing symbols |
| --- | --- | --- |
| Open app | Bind saved settings, refresh every two seconds | No startup scheduling or cancellation. Activity `onCreate`, `refresh`; Control `setEnabled` and `save` are called only by explicit listeners. |
| Setup | Edit endpoint, enter token and interval, Save settings | Validate, save under mutex, clear entered token, refresh. Activity `onCreate` save listener; HTTP `validateUrl`; Control `save`. |
| OFF | Explicit switch ON, gate enabled only | Persist intent, schedule periodic worker only if readback matches. Control `setEnabled`; Worker `Schedule.periodic`. |
| ON | Explicit switch OFF | Persist OFF, cancel periodic, manual, and delivery-retry work; separate webhook-test is excluded. Control `setEnabled`; Worker `Schedule.pauseHealth`. |
| Configured | Send test | Enqueue isolated one-shot empty batch, independently of switch or health permissions. Activity `refresh`, `onCreate`; Worker `Schedule.manual`, `SyncWorker.doWork`; Coordinator `run`, `EmptyTest.body`. |
| ON, configured, permissions granted | Manual health action, gate enabled only | Enqueue non-test worker. In the current gated build this control is disabled with the resource-safety reason. Activity `refresh`, `onCreate`; Coordinator `run`. |

## State matrix

The closed build gate takes precedence over every effective status below. The screen shows Build gated with "Health sync unavailable in this build - resource safety pending". Saved consent is labelled separately. OFF consent cannot be enabled in this build; saved ON consent remains checked and can be turned OFF. The manual health action is disabled. Configured empty Test remains available regardless of consent, permissions, or legacy Pending. Rendering changes no consent and makes no scheduler calls. Display `controls`, `consentLabel`, `format`; Control `setEnabled`; Activity `onCreate`, `refresh`.

Product decision (b) changes the old closed-gate OFF presentation to Build gated. Existing status-mapping assertions now explicitly use gate-enabled snapshots and retain their exact expected values. New closed-gate cases verify the changed product behavior. Unless a row explicitly describes the closed gate, effective-status mappings below describe a gate-enabled build; recorded progress and historical results remain read-only.

## Boundaries

| Constraint | Implementation |
| --- | --- |
| Test has no health records and no automatic retry | Coordinator `EmptyTest.body`, `run`; HTTP `client` disables connection retry and redirects; Worker `SyncWorker.doWork` returns success after coordinator completion. |
| Health access is separate from empty testing | Activity `refresh` enables Send test using configuration only; `onCreate` permission dialog and permission launcher are separate. |
| Retained data does not unlock on Save or Test | Activity `onCreate` save lock check; Coordinator `run` has no Pending or cursor mutation. |
| Display has no delivery authority | Display `Snapshot`, `format`, `testResult`, `progress` format read-only inputs. Activity `refresh` binds them. |
